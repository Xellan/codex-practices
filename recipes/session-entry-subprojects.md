# Единая точка входа сессии в подпроектах

## Как вызвать

«Почини доставку стартового контекста в подпроектах», «сессия в подпроекте
не видит общего состояния», «сделай, чтобы эстафета приходила из любого окна».
Откат: «убери точку входа из подпроектов» — тот же скрипт раскладки удаляет
вызов из настроек, ничего не оставляя.

Практика — продолжение
[`parallel-subprojects-shared-memory.md`](parallel-subprojects-shared-memory.md):
там подпроекты заводятся, здесь чинится доставка стартового контекста в них.

## Кому это нужно

Тем, кто уже работает по схеме «подпроект = отдельное окно» и заметил, что
окна подпроектов стартуют «слепыми». Настройку делает самый технический член
команды — или Claude Code по запросу (уровень 1); настройка **разовая**,
дальше механизм работает сам, и **выгоду получают все окна**: юрист в окне
дела, аналитик в окне направления, консультант в окне клиента начинают сессию
с полной картиной без единого действия.

Отделите свой случай: если контекст не приходит **нигде, включая корень**, —
механизма доставки ещё нет, начните с настройки по
[`session-handoff.md`](session-handoff.md); эта практика чинит уже работающую
доставку для подпроектов.

**Сначала проверьте, нужна ли вам раскладка (донастройка каждого подпроекта)
вообще.** Если подпроекты — это подкаталоги одного git-репозитория (монорепа),
настройки корня в них действуют, и
чинить надо только сам скрипт доставки (причины 1–2 ниже). Раскладка по
подпроектам нужна, только когда у подпроектов **свои** папки настроек —
отдельные деревья, заведённые по рецепту v1.9.

## Проблема: «контекст подтягивается не всегда»

Стартовый документ состояния ([`session-handoff.md`](session-handoff.md))
доставляет в модель SessionStart hook — автоматический механизм, который
Claude Code исполняет при старте сессии. Наивная реализация берёт файл по пути
корня — и работает только из корня. Симптом плавающий: где-то работает, где-то
нет, и это списывают на случайность.

За симптомом — три независимые причины:

1. **Переменная указывает не туда.** В окне подпроекта «каталог проекта» —
   это каталог подпроекта. Файла эстафеты там нет, механизм молчит — а
   молчание внешне неотличимо от «механизма нет вовсе»: страховка от падения
   старта маскирует и настоящую неудачу.
2. **Частичное срабатывание хуже отказа.** В части подпроектов есть свой
   документ состояния — механизм отдаёт его, а общий корневой не отдаёт
   никогда. Модель знает свой участок и не знает о кросс-режущем и горящем.
3. **Настройки не наследуются** — но только между отдельными деревьями.
   У подпроектов со своими папками настроек починка корня ничего не меняет;
   в монорепе этой причины нет.

Пока причины не разделены, любая «починка» лечит одну и оставляет симптом
плавать.

## Решение — пять принципов

1. **Логика в скрипте, не в строке настроек.** Однострочник нечитаем,
   не тестируется и дублируется; скрипт один, вызывается всеми одинаково.
2. **Скрипт сам находит корень — и берёт самый верхний из совпавших.**
   Поиск вверх по дереву по паре признаков (файл состояния + каталог архива).
   ★ Одного «первого совпавшего снизу» мало: по канону пакета зрелый
   подпроект имеет **такую же пару** (своя эстафета + свой архив) — и стал бы
   ложным корнем. Поэтому поиск идёт до вершины и запоминает последнее
   совпадение; ещё надёжнее — явный маркер корня в корневом CLAUDE.md.
3. **Отдавать оба уровня и печатать пути.** Ядро корневого документа —
   плюс явные полные пути: к корневому документу целиком и к документам
   подпроекта (эстафета, состояние, идентичность — что есть). Инжектируется
   только ядро (у поля доставки есть предел объёма) — доборка возможна лишь
   в том случае, если сессия знает, **где** лежит полный документ.
4. **Раскладка по подпроектам — скриптом.** Как раскладывать (идемпотентность,
   сухой прогон, видимое отсечение служебных каталогов) — владелец этого
   факта — каркасный рецепт [`rule-enforcement-hooks.md`](rule-enforcement-hooks.md),
   раздел «Границы охвата»; здесь — только специфика: раскладывается вызов
   одного общего скрипта, существующие настройки подпроектов сохраняются.
5. **Защита от чужого проекта.** Запасной якорь на абсолютный путь
   применяется только внутри своего дерева; вне его — тихий выход, иначе
   ваша эстафета приедет в сессию постороннего проекта.

Правило владения — прямым текстом в доставляемом сообщении: кросс-режущее
и горящее — в корневом документе, статус участка — в документах подпроекта,
одно другое не заменяет.

## Проверка — обязательная: четыре сценария скрипта + один живой

Механизм легко «починить» так, что он молчит: неудачу маскирует страховка
от падения. Прогон скрипта вручную с подстановкой переменной:

| Сценарий | Ожидание |
|-|-|
| корень проекта | ядро корневого документа + путь к полному |
| подпроект без своего документа | ядро корневого + пометка «в подпроекте» |
| подпроект со своим документом | оба уровня, пути к обоим |
| зрелый подпроект (своя эстафета + свой архив) | корнем выбран верхний, не подпроект |
| чужой проект | пусто |

★ Четыре сценария проверяют **скрипт**, но не **доставку**: они не поймают
отсутствующую зависимость (скрипту нужен `jq` — установка и ограничения
описаны в [`session-handoff.md`](session-handoff.md), раздел «Зависимости
и ограничения»),
вызов не в том файле настроек или доставленный, но проигнорированный контекст.
Поэтому пятый сценарий — **живой**: выйти, открыть новую сессию в окне
подпроекта и задать контрольный вопрос («статус работ по проекту?»), не
подсказывая про эстафету. Факты корневого документа в ответе — доставка
работает; их нет — см. диагностику в session-handoff.

Формула приёмки для неспециалиста — именно пятый сценарий: не «покажи прогон
скрипта», а **«покажи живой старт из окна подпроекта»**.

После массовой раскладки — проверка целостности всех файлов настроек
(валидный JSON). ★ Грабля: перебор результатов поиска циклом по словам
разбивает пути с пробелами — валидные файлы выглядят битыми; использовать
нуль-разделители (`find … -print0` + `xargs -0` или `while read -d ''`).

## Уровни настройки

**Уровень 0 — регистрация в CLAUDE.md:**

```markdown
<!-- [claude-code-practices v1.10] BEGIN: session-entry-subprojects -->
## Точка входа сессии в подпроектах

Стартовый контекст должен приходить из любого окна дерева. Если сессия
подпроекта не видит общего состояния — попроси: «почини точку входа
в подпроектах». Приёмка — живой старт из окна подпроекта, не прогон скрипта.
<!-- [claude-code-practices v1.10] END: session-entry-subprojects -->
```

**Уровень 1** — попросить Claude Code настроить; принимать по живому
сценарию из окна подпроекта.
**Уровень 2 (для разработчиков)** — написать скрипт по схеме:

```bash
set -u
start="${CLAUDE_PROJECT_DIR:-$PWD}"

root=""; d="$start"                       # вверх до вершины, берём ПОСЛЕДНЕЕ совпадение
for _ in 1 2 3 4 5 6 7 8; do              # лимит глубины; поднимите при большей вложенности
  [ -f "$d/<файл-состояния>" ] && [ -d "$d/<каталог-архива>" ] && root="$d"
  parent=$(dirname "$d"); [ "$parent" = "$d" ] && break; d="$parent"
done

case "$start" in                          # запасной якорь ТОЛЬКО внутри своего дерева;
  <путь-к-корню>*|<вариант-пути>*)        # на Windows перечислите через | варианты
    [ -z "$root" ] && root="<путь-к-корню>" ;;   # написания диска и разделителей
esac
[ -z "$root" ] && exit 0                  # чужой проект — тихий выход

{
  echo "# ТОЧКА ВХОДА СЕССИИ"
  echo "Корень: $root — полный документ: $root/<файл-состояния> (читать целиком)"
  if [ "$start" != "$root" ]; then
    echo "Сессия в ПОДПРОЕКТЕ: $start"
    for f in <файл-состояния> <файл-идентичности> README.md; do
      [ -f "$start/$f" ] && echo "Документ подпроекта: $start/$f"
    done
  fi
  echo "Правило владения: кросс-режущее и горящее — в корневом документе;"
  echo "статус участка — в документах подпроекта; одно другое не заменяет."
  echo "## ЯДРО КОРНЕВОГО ДОКУМЕНТА"
  head -n <N-строк-ядра> "$root/<файл-состояния>" | tr -d '\r'
  echo "[...обрезано; полный документ по пути выше обязателен]"
} | jq -Rs '{hookSpecificOutput: {hookEventName: "SessionStart", additionalContext: .}}' \
  || true   # не ронять старт сессии; отказ ищется живым сценарием приёмки, не здесь
```

`tr -d '\r'` обязателен на Windows: возврат каретки ломает JSON. Плейсхолдеры
в угловых скобках заменяются на конвенции вашего проекта.

## Как это выглядит в разных практиках

- **Разработчик:** отдельные деревья сервисов — сессия сервиса видит общий
  статус и свой; в монорепе — только починка скрипта, без раскладки.
- **Юрист:** дела как подпроекты — окно дела получает общую картину практики
  (горящие сроки по всем делам) и досье своего дела.
- **Бухгалтер/аналитик:** отчётные направления — сессия направления знает
  общий календарь закрытия и статус участка.
- **Консультант-пресейл:** клиенты как подпроекты — окно клиента видит общую
  загрузку и состояние своей сделки.

## Когда НЕ применять

- Подпроектов нет — достаточно доставки из [`session-handoff.md`](session-handoff.md).
- Подпроекты полностью независимы (общего состояния нет) — доставлять нечего.
- Подпроекты — подкаталоги монорепы и симптомов 1–2 нет — ничего чинить
  не нужно.
- Часть окон не должна видеть общее состояние (внешние исполнители, чужой
  подряд) — эта схема доставляет ядро корня во **все** окна дерева;
  сегментируйте доставку, прежде чем раскладывать.

## Что делает Claude Code при настройке этой практики

*(Инструкция для Claude Code; пользователю читать необязательно.)*

Перед настройкой определить топологию: монорепа (раскладка не нужна) или
отдельные деревья. Скрипт — один общий; проверка зависимости `jq` — до записи
в настройки; раскладка — по правилам каркасного рецепта, с сухим прогоном
и показом списка оператору.

### Строгие правила (что НЕ делать)

1. **НЕ раскладывать без сухого прогона и показанного списка** каталогов
   (целевых и отсеянных).
2. **НЕ заявлять «настроено» без живого сценария** из окна подпроекта.
3. **НЕ заменять существующие настройки подпроектов** — дописывать вызов,
   сохраняя всё остальное.
4. **НЕ раскладывать в монорепе** — там настройки корня действуют сами.
5. **НЕ полагаться на «первое совпадение снизу» при поиске корня** — зрелый
   подпроект даёт ложный корень.
6. **Если в проекте есть скрипт заведения подпроекта — проверить, ставит ли он
   вызов точки входа.** Инструмент, создающий конфигурацию, создаёт её полной
   по чек-листу; полевой прецедент: скрипт заведения ставил настройки,
   идентичность и состояние — а точку входа дважды дописывали руками. Пока
   инструмент не исправлен — известное ограничение в его описании.
