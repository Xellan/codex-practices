# Приёмка Behavior Rules — модуль №2

Сценарии проверяются при разработке/установке, **не при каждой сессии Codex**. Эта таблица не означает, что проведён реальный E2E-прогон.

| № | Вход / условие | Ожидаемый результат |
| --- | --- | --- |
| BR-01 | G1=DevOps, G2=кратко, G3=сбалансированно | Компактный глобальный набор + диагностика; без навязанного TDD |
| BR-02 | G1=аналитика; нет инженерного стека | Не добавлять Docker, CI, production, TDD |
| BR-03 | Проект уже содержит правило «не трогай несвязанные файлы» | CORE-SCOPE не дублируется глобально или проектно |
| BR-04 | G3=автономно, G6=всё необратимое согласовывать | Вопрос об одном конфликте; не повторять остальные вопросы |
| BR-05 | Есть подтверждённые G2/G7 | Применить стиль общения без повторного Q&A |
| BR-06 | Пользователь не дал предпочтения языку | Не выбирать язык из предположений |
| BR-07 | Пользователь исключил одну рекомендацию | Уважать выбор; не восстанавливать на повторном запуске из шаблона |
| BR-08 | Пользователь отредактировал управляемый блок | Предпросмотр и явное согласие на изменение, сохранить остальное |
| BR-09 | Есть AGENTS.override.md | Не изменять заведомо неактивный AGENTS.md |
| BR-10 | В проекте принят TDD, существуют команды тестов | Контекстное правило локально, без повторения глобальных |
| BR-11 | В проекте нет подтверждённых команд проверки | Не изобретать тестовые команды или процесс CI |
| BR-12 | Пользователь просит автоматическую блокировку всех опасных команд текстом | Разъяснить границы AGENTS.md; не обещать принудительного механизма |
| BR-13 | Первый модуль собрал ответы Q&A | Второй использует те же ответы без отдельной анкеты или отдельного файла профиля |
| BR-14 | Повторное применение того же профиля | Один набор без дублей и лишних бэкапов; отсутствие реальных изменений |
| BR-15 | Настройка глобального и проектного AGENTS.md | Одна общая процедура предпросмотра/подтверждения/записи, а не два конкурирующих установщика |
| BR-16 | Обычный запуск Codex после установки | Не добавляются проверки, хуки, модельные вызовы или фоновые процессы |

## Ручные проверки перед объединением PR

1. Проверить ссылки из CODEX-START.md, setup-agents-md.md, шаблонов и этого файла.
2. Убедиться, что RULES-таблица остаётся только в рецепте, а не целиком вставляется в AGENTS.md.
3. На двух тестовых профилях сравнить предложенные правила (DevOps, аналитика).
4. Повторно запустить настройку на копии AGENTS.md с пользовательскими разделами.
5. Сохранить запрет на самовольную запись и отсутствие автопроверок в обычных сессиях.

Сценарии описывают **ожидаемое поведение Markdown-установщика**. Автоматизированного детерминированного rule-engine в этой версии нет.
