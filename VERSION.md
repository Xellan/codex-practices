## Changelog

### 1.10.1 (2026-08-09)

Правка по полевой проверке v1.10 на реальном проекте (накат пакета и работа под ним, а не чтение текстов). Три дефекта, которых не увидели ни коллегия ревьюверов, ни страховки, ни внешний контур — они проявляются только при исполнении практики.

- **Правило самодостаточности проекта в START.md.** Блоки практик отсылали к рецепту по пути внутрь каталога пакета — а пакет для проекта всегда внешний: его переносят и удаляют после настройки, а чтение вне проекта требует отдельного разрешения и в неинтерактивном режиме молча отклоняется. Теперь при установке любой практики: блок операционно самодостаточен (шаги, команды, приёмка — в нём), рецепт копируется внутрь проекта, ссылки блока относительные, установка идемпотентна (блок с той же меткой заменяется, а не дублируется — полевой дефект: задвоился). Локальная копия рецепта не нарушает карту владельцев: это версионированный снимок, владелец версии — метка блока.
- **Блок гардрейла стал исполнимым**: три шага с командами, карантин, особый порядок для пакетов, деловой триаж находки — прямо в блоке; ссылка на локальную копию рецепта. Раньше блок был регистрацией правила без процедуры.
- **Приёмка практики артефактами, не самоотчётом** (`guardrail-external.md`): на вопрос «ты использовал гардрейл?» модель уверенно отвечает «да», хотя страница затянута в контекст напрямую мимо процедуры, а практика в проекте не установлена. Фальсифицируемый вопрос — «покажи путь карантина и вердикт детектора».
- **Калибровка ожиданий от детектора** (там же, полевые цифры): сгенерированный по списку классов детектор поймал меньше половины закладок независимого набора; промежуточная «улучшенная» версия дала почти полную полноту и оказалась мусором — один сломанный класс срабатывал на любом тексте, поднимая обе цифры сразу. Отрицательный набор обязателен; рост полноты без падения ложных тревог — повод искать сломанный класс. Детектор — грубый фильтр, а не щит.
- Тот же путь-в-пакет исправлен в блоке `session-handoff.md`.

### 1.10 (2026-08-08)

Релиз «Механизм вместо надежды». Полевая база — эксплуатация пакета на зрелых рабочих проектах; главная эмпирика: правило, записанное в CLAUDE.md и продублированное в памяти, соблюдалось примерно в одном случае из шестидесяти, а hook рядом срабатывал всегда. Каждый рецепт прошёл коллегию из трёх агентов-ревьюверов (архитектор, аналитик коммуникаций с тестом четырёх профилей читателей, бизнес-критик) с состязательной доработкой.

- **Новый рецепт `rule-enforcement-hooks.md` «Критичное правило обеспечивается механизмом»** — каркас релиза: критерий отбора «обратимость последствия × выход за периметр», таблица «тип правила → механизм» (SessionStart / запрет / подтверждение / напоминание), паттерн блокировки с инструкцией и видимым обходом, обязательная таблица испытаний до подключения (включая сценарий «то же действие другим инструментом»), боевая проверка после, раскладка по подпроектам, уровни 0/1/2, раздел для Claude Code со строгими правилами.
- **Новый рецепт `guardrail-external.md` «Гардрейл внешнего контента»** — защита от промпт-инъекций: процедура «скачать как данные → детектор → читать с закрытыми действиями», граница по классу действий (пока внешний текст в контексте — необратимое через подтверждение), изолированный читатель для высоких ставок, детектор с открытой таксономией и закрытыми сигнатурами, вывод только фрагмента находки, карантин находок (не переносить в документы состояния), независимые испытания с приёмкой «в две цифры», особый порядок для пакетов (получение содержимого без исполнения установочных сценариев), честные строки охвата.
- **Новый рецепт `session-entry-subprojects.md` «Единая точка входа сессии в подпроектах»** — доводит v1.9: три причины плавающего симптома «контекст подтягивается не всегда», сегментация «монорепа vs отдельные деревья», поиск корня по паре признаков с выбором верхнего совпадения (защита от ложного корня зрелого подпроекта), доставка обоих уровней с печатью путей, защита от чужого проекта, приёмка пятью сценариями включая живой старт из окна подпроекта.
- **Новый рецепт `state-owner-not-filesystem.md` «Состояние читается у владельца»** — дисциплина чтения, парная к fact-ownership: правило шести пунктов (дата владельца как договор свежести, вопрос оператору о параллельных окнах, обновление владельца по роли пишущего, вывод снимком с датой, срок годности статусного факта из внешней системы), таблица «вопрос — источник», приёмка живым вопросом, калибровочный раздел «почему здесь нет механизма».
- **Двухслойная память** — дополнение `setup-memory.md`: раздел «Когда индекс перерос лимит» (горячее ядро: всегда-активные записи + указатели тем; холодные под-индексы; классификация в момент записи с носителем-блоком в CLAUDE.md; правило отбора по цене молчания; критерий выбытия из ядра; промах маршрутизации как карточка ловушки; четыре канарейки приёмки), лестница «куда класть запись — три вопроса» вместо старой типологии inline/reference, порядок записей индекса по критичности.
- **Три привычки проверки** — разложены по владельцам тем (решение коллегии, подтверждено оператором): контрольная выборка для гипотезы + запись отрицательного результата (behavior-rules, правило 4), срок годности статусного факта (state-owner-not-filesystem, п. 6), полнота выхода инструмента (session-entry-subprojects, строгое правило 6 + behavior-rules, правило 8), тихие частичные потери (contract-before-work, «QA без плана»). Именованный корень у Anti-Hallucination: «три способа, которыми проверка выглядит сделанной: объяснение вместо проверки, вчерашняя проверка вместо сегодняшней, запуск вместо выхода».
- **Самопроверка документации** (fact-ownership + шаблон скрипта): инвариант размера индекса получил порог предупреждения ~80% (сигнал до молчаливой потери, а не после), проверка сирот памяти стала двусторонней (файл без записи в индексе — молчаливый отказ), новый инвариант внутренней консистентности владельца с составной структурой (шапка == журнал).
- **Отстройки от v1.9:** в parallel-subprojects уточнён отвергнутый тупик хука доставки (отвергнут наивный вариант, рабочее решение — session-entry-subprojects) и добавлена ссылка на деление индекса; в session-handoff — отсылка от совета про монорепу к двухуровневому решению.

### 1.8 (2026-06-10)

Релиз «Гигиена документации». Основан на аудите зрелого проекта через 3 месяца эксплуатации пакета (~80 дефектов, 100% критичных — дубли изменчивого состояния) + валидации на четырёх других контекстах: болезнь воспроизвелась везде, включая сам пакет.

- **Новый рецепт `fact-ownership.md` «Один факт — один владелец»**: карта владельцев изменчивых фактов, чек-листы на событиях-источниках, анти-паттерны (снимок эстафеты в CLAUDE.md, индекс как второй носитель, хардкод среды в агентах), самопроверка документации — от ручной проверки по запросу до генерации скрипта инвариантов (для разработчиков). Killer-формулировка: «копия не бывает актуальной: либо ссылка, либо дефект».
- **Инвентаризация v2** (`project-inventory.md`): машинная самопроверка прежде глаз (шаг 0), запрет «актуализации» дублей — дубль устраняется заменой на ссылку, явная зона покрытия, регресс-трекинг через `audits/`, мандат исполнителя. Старый шаг «актуализируй CLAUDE.md» был анти-паттерном: исполнитель обновлял значение копии, и она протухала снова.
- **Правило 8 в `behavior-rules.md` «Профилактика на записи > периодическая уборка»**: у повторяющегося дефекта документации есть событие-источник; чек-лист на событии закрывает кран, уборка только выгребает лужу. Симметрия с правилом 7: оба — «механизм > надежда».
- **Уточнено правило 7**: в начале CLAUDE.md — триггер-ссылка без пересказа содержимого (пересказ протухает, ссылка — нет); упоминание mtime-lookup заменено на invariant-pointer LATEST.
- **Память** (`setup-memory.md`): документированный лимит автозагрузки MEMORY.md — первые 200 строк или 25 KB, что наступит раньше; хвост обрезается молча. Запись индекса — указатель ≤200 символов, не носитель. Проверка сирот в обе стороны. Критерий разделения хранилищ («секреты — только в локальной памяти проекта»).
- **Эстафета** (`session-handoff.md`): жизненный цикл — архив, INDEX-реестр, канонический чек-лист новой версии; анти-паттерн «пересказ эстафеты в CLAUDE.md» с эмпирикой (пересказ пережил 4 версии и дезинформировал 8 дней).
- **Агенты** (`create-agents.md`): четыре правила гигиены — общие правила ссылкой, факты среды не хардкодить (кейс: налоговая ставка в трёх агентах устарела при смене закона), уроки через память, секции «Когда использовать / Когда НЕ».
- **Dogfooding**: сам пакет вылечен по собственному рецепту — номер версии теперь живёт только в VERSION.md, счётчик рецептов — только в README.
- START.md: пункт 2.4.1 «Карта владельцев фактов + самопроверка документации»; описание инвентаризации обновлено.
- **Механизм обновления инсталляций**: при повторном запуске START сравнивает версии в метках блоков CLAUDE.md с версией пакета и предлагает обновить устаревшие блоки (в первую очередь — блок «Инвентаризация» версий до 1.8 с анти-паттерном «актуализация»). Также проверяются новые под-практики внутри уже настроенных пунктов. Раньше обновление доносило только новые пункты чеклиста — исправления внутри существующих практик молча не доезжали.
- README: принцип 8 «Один владелец > актуальные копии».

## Процедура обновления

При переходе на новую версию пакета:
1. Скачайте новую версию
2. Запустите START.md — он обнаружит метки старой версии в CLAUDE.md
3. Покажет изменённые секции и спросит подтверждение
4. Обновит помеченные секции, не трогая пользовательские
